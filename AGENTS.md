# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This repo is a personal configuration for [Herdr](https://herdr.dev), a terminal workspace manager for AI coding agents. There is no application code — the deliverable is `config.toml` plus the two shell scripts that install it. `CLAUDE.md` is just a pointer to this file.

## Commands

```sh
./install-local.sh                                       # install config.toml from this checkout
bash -c "$(curl -fsSL https://raw.githubusercontent.com/kyleczhang/herdr-config/main/install.sh)"   # install from GitHub

HERDR_CONFIG_PATH=./config.toml herdr config check       # validate this repo's config without installing it
herdr --default-config                                   # full reference of every option and its default
herdr server reload-config                               # hot-reload config.toml in a running server
```

`herdr config check` against `HERDR_CONFIG_PATH=./config.toml` is the test suite here — run it after any edit to `config.toml`. Both install scripts already run it and abort before touching the real config if it fails.

## Architecture

**`config.toml`** installs to `${HERDR_CONFIG_PATH:-${XDG_CONFIG_HOME:-~/.config}/herdr/config.toml}`. It deliberately lists **only non-default values** — do not add an option just to restate its default, and check `herdr --default-config` before adding one. Sections in use: `[keys]`, `[theme]`, `[ui]`, `[ui.toast]`, `[ui.sound]`, `[ui.sidebar.spaces]`, `[ui.sidebar.agents]`.

The `[keys]` block is organized by sidebar area rather than by action, and that grouping is load-bearing: each area owns one modifier, and number jumps and `n`/`p` cycling within an area share it — tabs use `prefix` plain, spaces use `prefix+shift`, agents use `prefix+alt`. A new binding belongs to whichever area's modifier it extends (e.g. `new_workspace = "prefix+shift+c"` parallels the default `new_tab = "prefix+c"`). Area groups also hold that area's non-navigation bindings — `rename_tab = "prefix+r"` sits under `# Tabs` because `prefix` plain is the tabs modifier — and `""` unbinds an action outright, which is how `resize_mode = ""` frees `prefix+r`.

Sidebar `rows` are arrays of lines; each line is an array of cells, where a cell is either a bare token string (`"state_icon"`, `"tab"`, `"agent"`) or an inline table adding style (`{ token = "branch", fg = "#8839ef" }`). Colors are hard-coded hex values matched to the `catppuccin-latte` theme set in `[theme]`, so changing the theme means revisiting them.

**`install.sh` / `install-local.sh`** are the same pipeline (validate → back up existing config with a timestamp suffix → copy → reload a running server) differing only in source: `install.sh` curls `config.toml` from `main` on GitHub, `install-local.sh` uses the file next to the script. Keep the two in sync when changing install behavior. Validation and reload are both skipped when the `herdr` binary isn't on `PATH`, so the scripts work on a machine where Herdr isn't installed yet.

## Commit messages

Keep commit messages plain. **Do not add `Co-Authored-By` trailers or any other "generated by AI / co-authored with an assistant" attribution.**

## Writing markdown

When writing or editing any markdown file (plan docs, this file, etc.), do not hard-wrap paragraphs or insert arbitrary line breaks to keep lines short. Ignore line-length limits entirely — let each paragraph be a single long line and rely on the editor's soft wrap. Only break lines where a break is semantically meaningful (separate paragraphs, list items, headings).
